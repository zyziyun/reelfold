千剪（Reelfold）不自带 AI，用的是你已经有的：已经登录的 Claude Code 或 Codex 命令行、你自己安装并登录的其他编程助手、你自己选的服务商的 API key，或者跑在你自己电脑上的模型。你设一个默认，也可以只为某次请求、某个项目或某项任务换一个 AI。

## 为什么重要

花多少钱、效果怎么样、文字发到哪里，都由你决定。已经在付费的订阅可以直接拿来做规划，不额外花钱；本地模型能让一切留在你的 Mac 上。某个服务商挂了或者登录过期，备用模型可以顶上，并且会明确告诉你这次是谁回答的。

## 哪些步骤会用到 AI

| 步骤 | AI 做什么 |
|---|---|
| 接单 | 把你的一句话和素材变成计划 |
| 选段规划 | 从长录像里挑出要切的片段，配标题和 hook |
| 字幕校对和术语表 | 修正语音识别听错的人名和术语 |
| 发布文案和脚本 | 写标题、正文、口播稿 |
| 成片二次编辑和对话 | 把一句话的修改要求变成具体编辑步骤；驱动项目对话和成片对话 |
| 自动驾驶的选择 | 判断拿不准的选择（口头禅、开头、封面、配乐），并给出理由 |
| 讲解视频的画面 | 根据讲稿起草脚本，把每一段画成图解或动画 |

语音识别和配音是另外两套：转写默认在本地跑（Apple Silicon 上的 whisper），配音可以用免费的本地声音、你自己的克隆声音，或者在线服务（见 [配音](/docs/zh/guides/voices/)）。大多数文字类步骤在完全没有模型时也能跑，走规则方案。画讲解视频的场景是例外：必须有模型；没有时项目会停在「要你看」，不会做出只有文字的视频。

## 接入方式

| 方式 | 支持的服务 | 说明 |
|---|---|---|
| 命令行登录，不用 API key | Claude Code、Codex | 用你已登录的订阅。运行时不开放任何工具，在一个空的临时文件夹里跑，不会往你的项目里写东西 |
| 编程助手（ACP），不用 API key | Gemini CLI、Cursor CLI、GitHub Copilot CLI、OpenCode、通过 ACP 适配器的 Claude Code 和 Codex、Qwen Code（阿里）、Kimi CLI（月之暗面）、CodeBuddy（腾讯）、iFlow CLI | 你自己安装并登录的任何助手，通过 Agent Client Protocol 驱动。千剪运行你自己的程序、用它自己的登录，在空文件夹里跑，拒绝一切工具调用，从不接触你的账号 |
| API key | Anthropic、OpenAI、DeepSeek、通义千问 Qwen、Kimi、智谱 GLM、豆包、OpenRouter、Gemini；配音用 ElevenLabs | 配置文件里只写环境变量名，不写 key 本身。Qwen、Kimi、GLM 和豆包的 key 可选中国大陆或国际接入点 |
| 本地 | Ollama、LM Studio、vLLM、llama.cpp；本地 whisper；你自己的 whisper 或 TTS 服务 | 数据不离开你的电脑 |

### 在中国大陆

Qwen Code、Kimi CLI 和 CodeBuddy 在中国大陆可以直接用；设置 › AI › **编程助手** 会给每个助手标上 **国内可直接用**、**国内部分可用** 或 **需要海外网络**。API key 方面，通义千问（阿里云百炼）、Kimi（月之暗面）、智谱 GLM 和豆包（火山方舟，和 Seedance 用同一个 key）可以选 **接入点**：**中国大陆** 或 **国际**，和 key 在哪里创建的对应。DeepSeek 只有一个接入点。服务商回答「你所在的地区不可用」时，千剪会直接说明，并由备用顺序里的下一个 AI 回答。

:::note[订阅命令行是给你自己用的]
Claude Code 和 Codex 的订阅有各自的用量限制和使用条款。如果要用它们大批量做收费的客户项目，先看清服务商当前的条款，条款要求的地方改用 API key 或本地模型。
:::

## 按请求、项目或分组选 AI

设置 › AI 里是你的**默认** AI。你也可以只换一部分：

- **某次请求。** 输入框（首页、工作室、「多条视频」）在平台旁边有一个 AI 标签。它显示你的默认（比如「Claude Code · Opus 5.5」）；选另一个可用的 AI 和模型，只对这次请求生效。项目会记住它，这个项目的每个 AI 步骤都用它，失败时按你的备用顺序往下试。
- **某个项目。** 在项目的运行页、项目页或成片对话里切换它的 AI。从这个项目的下一个 AI 步骤起生效；正在跑的步骤不会被打断，切换会写进决策记录。列表里会显示项目自己的 AI。
- **项目对话里的 `/model`** 只切换这个项目，并在对话里说明。**设为我的默认** 把它设为新请求的默认 AI。
- **一个目标分组**（「多条视频」）可以把还没做好的视频全部切换，也可以只换其中一条；正在做的从下一个 AI 步骤起换。

## 模型

在设置 › AI 里为每个服务选 **模型**：Claude Code 可选 Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.1 或命令行默认；Codex 列出你的登录能用的模型；编程助手用它自己的模型列表；API key 用服务商的列表。某项工作仍然可以有自己的模型，AI 标签会显示并能切换它。在成片对话里，`/model` 显示当前在用的模型并给出选择器，`/model 5.5` 或 `/model sonnet` 直接切换。斜杠命令从不发给模型。

## 按任务分配和备用模型

每项任务（接单、选段规划、校对、术语表、文案、脚本、成片编辑）都可以单独指定模型，没单独指定的用默认。每条设置还可以按顺序列出备用模型：第一个失败了，就试下一个。某次运行里明确点名的模型不会切换到备用。

切到备用时，你会看到提示，而不是悄悄换掉：

- `llm-fallback`：「Claude Code 没成功（登录过期），改用了 Codex」。任务照常完成。
- `llm-all-failed`：链条里所有模型都失败了。这一步会停下并列出它们。有规则方案的地方（选段规划、接单）会用规则补上，并告诉你。

失败原因包括：登录过期、没登录、没安装、缺少 key、触发限流、超时。

## 费用

API 调用按 token 计费，每一步都会报告花费。订阅命令行和本地模型记为 0。内部测试里，一节 72 分钟的课切成 24 条、每条 4 个平台（共 96 个文件），API 总花费 0.73 美元，大约每条 0.03 美元。

## 时限和思考强度

- **时限。** 命令行模型（Claude Code、Codex）每次尝试都有时限，登录过期也不会把一步卡住。成片对话给它 180 秒，慢一点总比没有回答好。超时后会换备用链里的下一个，并告诉你（「Claude Code 在 120 秒内没有回应，这次用了 Codex」）；刚超时的命令行会被跳过一阵子。可以给某条路由设自己的时限（`timeout: 300`），或者给所有命令行调用设（`VSTUDIO_LLM_CLI_TIMEOUT=300`）。
- **思考强度。** 大的生成任务，比如画讲解视频的一段场景，会让 Claude Code 用中等思考强度（`--effort medium`）：每段大约一分钟，而不是五分钟。在路由上设 `effort:`（`low`、`medium`、`high`）可以改。不支持 `--effort` 的旧版 Claude Code 会不带它调用。
- **模型。** 不填模型就用命令行自己的默认模型。如果给 Codex 指定了模型，它必须是你的 ChatGPT 账号能用的；账号不支持的模型每次调用都会失败（「没有回应」）。

## 在 Mac App 里

设置 › **AI** 显示你的默认 AI、它是否正常和上次检查的时间，以及「换一个 AI…」。在这里登录 Claude Code 或 Codex（浏览器会打开），**测试**服务，为每个服务选**模型**，添加 **API 密钥**（存在系统钥匙串里），找**本机模型**，**调整顺序**设置备用，以及**高级：不同工作用不同 AI**。**编程助手** 显示哪些助手已安装、已登录，每个在国内能不能用，一键测试、登录、助手自己的模型列表，以及其他助手的安装命令；任何一个都可以用作某项工作的 AI 或备用（比如 Claude Code，然后 Qwen Code，然后 DeepSeek key）。换了密钥需要重启引擎，页面会提示。[Mac App Store 版](/docs/zh/help/editions/)只有 API 密钥和本地模型。

## 排查

| 看到的提示 | 意思 | 怎么办 |
|---|---|---|
| **未连接模型** /「还没连上 AI 模型」 | 什么都没连上，或者所有服务都用不了 | 设置 › AI：登录、添加密钥或启动本地模型，然后**测试** |
| 「模型这次没回应」/「Claude Code 没有回应」 | 连上了，但没有按时回复，或者出错了 | **重试**（会多等一会儿）；检查登录；在「调整顺序」里加一个备用 |
| 「… 登录已过期，这次用了 …」 | 第一个服务登录过期，备用回答了 | 在设置 › AI 里重新登录 |
| 「… 用量到上限了，这次用了 …」 | 你的套餐额度用完了，备用回答了 | 等额度恢复，或者把重活交给 API 密钥或本地模型 |
| Codex 每次调用都立刻失败 | 路由里给 Codex 指定的模型你的账号用不了 | 设置 › AI 会标出来并给出一键修复；或者清空模型，换一个账号支持的 |
| 「… 在你所在的地区不可用」 | 服务商不对你所在的地区开放 | 换一个在你那里能用的 AI（Qwen Code、Kimi、DeepSeek……），或设置 key 的 **接入点** |
| 「画面需要 AI 模型来画」 | 没有模型就画不了讲解视频的场景 | 连上一个，再点**重试** |

更多见 [问题排查](/docs/zh/help/troubleshooting/#ai-服务)。

## 用 Claude Code 技能

在 `persona.local.yaml` 里写一段 `llm:`：

```yaml
llm:
  default: {provider: claude-code, timeout: 300, fallback: [codex, ollama]}
  tasks:
    copy:      {provider: codex}                     # 不填模型：用命令行自己的默认
    proofread: {provider: ollama, model: "qwen3:8b"}
```

然后在 `lib/` 目录下检查：

```bash
python3 -m vstudio.llm providers   # 这台电脑上哪些能用；不会发送任何内容
python3 -m vstudio.llm route       # 每项任务用哪个模型，以及为什么
python3 -m vstudio.llm test --provider ollama --model llama3.2:1b   # 发一次很小的测试请求
```
